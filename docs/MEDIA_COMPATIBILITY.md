# 跨格式视频标注与兼容副本

适用于 `1.1.0.dev0` 开发版。此入口扩大可以人工标注的视频格式范围，不提供自动内容识别。原片能被本机 FFmpeg 解码、时间戳能建立可靠对应关系时，可以生成浏览器兼容副本，再使用通用片段编辑器。遇到损坏、加密、缺少解码器或无法验证的时间轴时明确失败，不生成一个看似可用的空项目。

## 准备与打开

安装本项目，并把包含 `libx264`、AAC 编码器的 `ffmpeg` 与 `ffprobe` 放入 PATH。需要支持 `-fps_mode`、`-enc_time_base`、`setts` 的 FFmpeg 版本；本机验收使用 FFmpeg 9。pip 不安装这两个可执行文件。全片检查与转换需要时间和额外磁盘空间，可以用 Ctrl+C 取消。

```powershell
trace-annotate video-open "D:\素材\input.mov" -o "D:\标注项目\input-project"
```

输出目录必须不存在，其父目录必须存在。成功后命令打开本机编辑器，自动加载兼容副本与项目元数据；保持终端运行即可播放和编辑。关闭服务使用 Ctrl+C。原片始终保留，输出不覆盖已有目录或文件。

只准备、不打开浏览器：

```powershell
trace-annotate video-prepare "D:\素材\input.mov" -o "D:\标注项目\input-project"
```

重新打开已有项目：

```powershell
trace-annotate video-ui --project "D:\标注项目\input-project"
```

加 `--no-browser` 会打印网址供手动打开，并继续提供本机服务。默认随机端口；`--port 8765` 可以固定端口。服务仅绑定 `127.0.0.1`，网址含随机访问令牌，不提供目录浏览、上传或覆盖写入。不要在停止服务后期待播放器继续读取尚未缓存的帧。

## 编辑与持久保存

在页面中填写起止秒数、自由标签、描述、标签集合与轨道，点击保存片段，再导出 JSON。`annotations.json` 是项目初始文件，服务只读；编辑后的主文件通过浏览器下载。下次打开项目后，从“导入 JSON”选择上次下载的完整主文件，继续编辑。

浏览器草稿保存已保存片段和未保存表单，但以浏览器 origin 为边界。随机端口重启后可能看不到上次草稿；固定端口可保持 origin，仍需保留 JSON 主文件。页面刷新会提示恢复草稿，不自动覆盖当前数据。缺失或篡改原片溯源、时间映射的 JSON 或草稿会被拒绝；单纯改变 JSON 对象键的排列顺序不会导致拒绝。

清空片段会保留兼容项目的原片溯源和时间映射。编辑器不会把未保存表单自动混入已保存 JSON；播放器或服务失败时，会明确询问是否只备份已保存片段，同时保留未保存文字。

## 项目文件与时间含义

| 文件 | 作用 |
|---|---|
| `playback.mp4` | H.264/yuv420p 视频与 AAC 音轨的兼容预览副本 |
| `annotations.json` | 绑定副本完整 SHA256 与大小的 schema v2 初始文档 |
| `project.json` | 原片/副本身份、编码转换、帧数、时间映射与限制 |
| `frame-map.jsonl` | 每个实际解码视频帧的原始 PTS、副本 PTS、时间与对应序号 |
| `preparation-log.json` | 工具版本、处理命令、退出码、探测结果、输出摘要与源文件前后校验 |

标注根字段 `clip/media_size/media_sha256/duration` 绑定 `playback.mp4`。`metadata.prepared_media` 保留原片文件名、大小、完整 SHA256、共同时间起点和映射引用。导出 JSON 时这些信息完整保留，CSV/字幕不具备同样的溯源能力。

声音可能早于首个视频帧。转换采用视频和所有音轨首个解码时间中的最早值作为共同起点，保持声音与画面的相对偏移：

```text
副本时间 = 原始呈现时间 - timeline.origin_time
原始呈现时间 = 副本时间 + timeline.origin_time
```

不使用名义 FPS 推算源帧，不强制变成固定帧率。原帧与副本帧逐一验证数量、顺序和时间戳；最后一帧的保持时长也核对。逐帧对应验证不代表浏览器已经实现逐帧导航；页面仍保存秒级定位。原片时间戳与流时间基数应结合 `frame-map.jsonl` 使用，不要把副本的秒数直接当成原始文件的绝对 PTS。

部分旧版 FFprobe 不在解码帧中给出末帧时长。此时读取同一视频流的数据包，只有所有数据包 PTS 与实际解码帧一一对应、没有重复或缺失，且末帧对应包有明确正时长，才使用该值。`timeline.last_frame_duration` 记录原片与副本的时长来源；没有可靠元数据时仍然拒绝，不按平均帧率、相邻帧间隔或容器总长猜测末帧保持时间。

音频保留所有可验证的音轨、声道及其相对起止时间，并核对编码后偏移。源音频验证连续后按样本钟播放，避免低精度时间基量化造成微小空隙；没有静默填补真实断音。AAC 有编码边界误差，具体容差写在 timeline.audio.tracks 中。部分 WMA 解码器最后一个 flush 音频帧没有 PTS；只有已知编码、前序连续、恰好最后一帧的情形，才按前帧终点和样本数推导，并在轨道记录中明确标记 `source_timestamp_basis/inferred_tail_frames`；中间缺时戳不会被猜补。视频仍要求逐帧原始 PTS。浏览器可能只播放默认音轨；当前页面没有多音轨切换控件。原片额外视频轨、字幕、封面和附件不自动转换为标注，未用于播放的流列在 manifest 中。

## 图像与 HDR

兼容副本是有损预览；原始图像和声音仍保存在原片。SDR 高位深视频会转为 8bit，全范围 MJPEG 等素材会转换为副本的有限范围像素值，奇数宽高通过边缘补齐保持原有像素区域，不裁掉最末列或行。旋转方向应用到副本画面。不要把预览副本当作母版或色彩测量真值。完整项目目录须连同 `project.json`、`frame-map.jsonl` 和处理日志一起保留；单独导出的 JSON 保存标注及溯源引用，不包含全部色彩转换参数和逐帧映射行。

HDR/PQ/HLG 默认要求显式选择色调映射：

```powershell
trace-annotate video-open "D:\素材\hdr.mov" -o "D:\标注项目\hdr-project" --tone-map-hdr
```

此选项把 HDR 映射到 SDR BT.709 供预览，依赖 FFmpeg 的 `zscale/tonemap` 等滤镜，转换过程记录在项目中。它不保留 HDR 原像素、动态元数据或显示亮度；原片不变。缺少必要滤镜、颜色信息无法处理或时间对应失败时，项目准备失败。需要精确颜色、亮度或 HDR 母版审核时，应直接使用相应专业流程。

## 支持边界与故障处理

实测格式覆盖 MP4、MOV/ProRes、MPEG-4 AVI、H.264 TS、MKV/FFV1、WebM VP8/VP9/AV1、HEVC，以及变帧率、旋转、奇数尺寸与4K样本。格式名不构成对其中所有编码组合的保证；最终以本机解码与实际编辑验收为准。

纯音频、文本伪装视频、零字节、损坏/截断、无可用视频帧、缺失或不可靠 PTS、不连续音频及无法验证的终点都会明确失败。联网播放列表、DRM 和外部依赖媒体不属于这个自包含本地文件入口。不可修复的文件应从原始来源重新取得完整素材。

准备失败不会覆盖既有项目；取消会终止本次子进程并清理本次临时产物。输出发布依赖硬链接，目标应使用 NTFS 等支持硬链接的本地文件系统；exFAT/FAT 或部分网络盘会明确失败。转换不设置一个伪造的“无限时长/大小支持”承诺，实际耗时、空间和解码能力由素材与本机资源决定。

## 复现验收

```powershell
python -m pytest tests/test_temporal_preparation.py tests/test_temporal_preparation_cli.py tests/test_temporal_project_server.py -q
python scripts/check_prepared_editor.py --output output/prepared-editor-check
```

输出目录须为新目录。浏览器脚本在隔离浏览器中生成 ProRes+AAC 和真实变帧率素材，实际转换、HTTP Range 播放、划段、下载、草稿恢复、重新导入与干净上下文重开。标签为操作测试夹具，不是自动识别预测。CI 保存对应工件；原生文件选择器、所有浏览器、所有素材与模型语义准确率仍需各自验证。

跨 FFmpeg 版本排查可运行 `python scripts/diagnose_media_timing.py --output output/timing-new`；使用 `--ffmpeg-dir` 指向独立工具目录可隔离比较版本。脚本只生成合成素材，保留原始流、帧、数据包、命令日志及失败现场，不绕过准备门禁、不读取用户素材。CI 测试失败时也会保存该诊断工件。
