# TraceAnnotate

Local media review and temporal video annotation tools for Python.

[![CI](https://github.com/wyregey779-dot/trace-annotate/actions/workflows/ci.yml/badge.svg)](https://github.com/wyregey779-dot/trace-annotate/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

[English](README.md) · [中文说明](README_CN.md) · [Quickstart](docs/QUICKSTART.md) · [Releases](https://github.com/wyregey779-dot/trace-annotate/releases)

TraceAnnotate supports local media review and temporal annotation. The development version adds general video segments with custom event labels, descriptions, tags and overlapping tracks. The embodied workflow keeps its working/idle intervals, step checks and verdicts. The Python library also provides batched media staging, field-level provenance and asset review helpers.

![Actual embodied editor, using a synthetic operation fixture](docs/media/embodied-editor.png)

[Actual editor/QC screenshots and a 12-second browser recording](docs/DEMO_MEDIA.md) show the development workflow. The recording uses synthetic media and explicit scripted labels; it does not establish video semantic accuracy.

## General video annotation (development version)

The new workflow is in `1.1.0.dev0`; the published `v1.0.2` release below does not include it. Install the current checkout with `python -m pip install -e ".[dev]"`, then run:

```bash
trace-annotate video-ui
trace-annotate video-open input.mov -o new-annotation-project
trace-annotate video-validate examples/annotations/general-video.json
trace-annotate video-export examples/annotations/general-video.json --format srt --track "字幕" -o output-subtitles.srt
```

Open a local video, mark and edit segments, and download native JSON to resume later. Events can overlap without being interpreted as working/idle or correct/incorrect. CSV, SRT and WebVTT are projections; retain JSON for IDs, tags, tracks, review state and metadata. Outputs from the new CLI commands must use new filenames. See [the general video guide](docs/GENERAL_VIDEO_ANNOTATION.md) for importing subtitles, recovery, format boundaries and the planned spatial annotation work.

New browser documents use schema v2 and bind annotations/drafts to the full media SHA-256, computed locally in a cancellable background Worker. Different content with matching filenames, sizes and durations is rejected. Legacy v1 imports require explicit migration and renewed review; verified content can be relinked after a rename. `video-hash` and `video-bind` expose hashing/binding in the CLI. Presented-frame timestamps are displayed separately from seek time; frame-accurate navigation remains planned.

For local formats the browser cannot play directly, use `video-open SOURCE -o NEW_PROJECT`. Local FFmpeg/ffprobe create an H.264/AAC playback copy, verify decoded frame correspondence and audio offsets, retain source identity, and open the editor through a read-only loopback server. Resume with `video-ui --project PROJECT` and import your downloaded JSON. HDR previews require explicit `--tone-map-hdr`; corrupt, encrypted or unverifiable inputs fail clearly. See the [media compatibility guide](docs/MEDIA_COMPATIBILITY.md).

## Start with a complete example

The quickstart takes a synthetic annotation document through idle calculation, validation, step comparison, an HTML report and SRT export. It requires no video file, model weights or API key.

```bash
git clone --branch v1.0.2 --depth 1 https://github.com/wyregey779-dot/trace-annotate.git
cd trace-annotate
python -m venv .venv
```

Activate the environment with `.venv\Scripts\Activate.ps1` in PowerShell or `source .venv/bin/activate` on Linux/macOS, then run:

```bash
python -m pip install .
python examples/run_quickstart.py --output output/quickstart
```

Expected final result:

```text
Verified: 2 working segments, 3 idle intervals, 5 subtitle entries.
```

Open `output/quickstart/qc-report.html` to inspect the report. The script also writes the processed `assembly.json` and `assembly.srt`. It refuses an existing output directory; choose a new path when rerunning it.

![QC report generated from the synthetic quickstart annotation](docs/images/quickstart-qc.jpg)

The screenshot shows the report generated by this fixture. Its labels are synthetic examples of the document format, not model predictions. See [the full walkthrough](docs/QUICKSTART.md) for individual commands, expected intervals and troubleshooting.

## What is available

| Area | Functionality | Status and scope |
| --- | --- | --- |
| Media preparation | Batched staging, source/staging boundary checks, in-use locks, file size and first-MiB MD5 checks | Local filesystem operations with regression tests |
| Asset review | Brightness/sharpness metrics, dHash clustering, configurable review rules and contact sheets | Review aids; labels require human judgment |
| Provenance | Per-field `fill` origins, human overrides, revision history and rollback | Python library |
| General video segments | Custom labels, text, tags, overlapping tracks, explicit review state, local editor and JSON/CSV/SRT/WebVTT | Development version; no bounding-box or object-tracking UI |
| Embodied annotation | Browser editor, working/idle complements, step reconciliation, interval validation and sampled agreement | Separate CLI and Python workflow |
| Reports and exchange | HTML QC, SRT, Label Studio configuration/parsing, CVAT-style XML and action-label text | Local format tests; external tool/version compatibility still needs round-trip verification |
| Optional vision/OCR | Motion, face, OCR and scene helpers | Depends on the relevant runtime, executable or local model |
| CLIP inference | Planned; adapter reports `not_run` | Complete image/text inference is not implemented |

## Install a release

Use Python 3.9 or newer. The core dependencies are NumPy, Pillow and tqdm. For package use without a source checkout, install the tagged source archive in a virtual environment:

```bash
python -m pip install "https://github.com/wyregey779-dot/trace-annotate/archive/refs/tags/v1.0.2.zip"
trace-annotate --version
trace-annotate --help
```

Core timeline processing runs locally without an OpenAI API key. Installation and optional model packages may need network access; prepare dependencies and weights before an offline session.

For development, install `python -m pip install -e ".[dev]"` from a source checkout and follow [CONTRIBUTING](CONTRIBUTING.md).

## Annotate and review your own video

```bash
trace-annotate embodied-ui
```

Choose a browser-supported local video, mark intervals, assign step numbers and review the verdicts, then export JSON. New segments start as **unjudged** (`无法判断`). Export your work before selecting a different video: loading new media resets the editor's annotations.

Use the CLI to process the exported document:

```bash
trace-annotate embodied-validate clip.json
trace-annotate embodied-diff clip.json --nsteps 5
trace-annotate embodied-qc clip.json -o qc-report.html
trace-annotate embodied-export clip.json --format srt -o clip.srt
```

The development version also provides `trace-annotate embodied-pipeline clip.json --nsteps 5 --report output/new-run/report.html`. This combines structural validation, declared procedure checks and optional comparison in one fail-closed run. Use a new report path and the actual media duration. [The quality pipeline guide](docs/QUALITY_PIPELINE.md) explains exit codes, review gates, safe idle repair and Windows launchers.

To recalculate idle intervals, run `trace-annotate embodied-idle clip.json --duration 60` with the actual video duration. It prints JSON by default; add `--inplace` only when you intend to update that file. Preserve the duration so the final idle interval is included.

See the [annotation SOP](docs/EMBODIED_ANNOTATION_SOP.md) for fields and label conventions. The two additional scripts in `examples/` demonstrate the asset pipeline and temporal agreement with synthetic data; the asset example uses simulated face/CLIP fields and creates/removes `examples/_demo_scratch`.

## Optional dependencies

From a source checkout, install only the extras needed for your workflow:

| Command or dependency | Purpose |
| --- | --- |
| `python -m pip install -e ".[cv]"` | OpenCV video/motion processing and optional HEIF support; YuNet face detection also needs compatible local ONNX weights |
| `python -m pip install -e ".[ocr]"` | RapidOCR integration; model/runtime availability depends on the installed package |
| `ffmpeg` executable on `PATH` | Scene-cut helper; pip does not install this executable |

The `clip` extra installs PyTorch/torchvision, but does not supply `cn_clip`, model weights or a complete inference path. The `full` extra installs optional dependencies without changing that limitation. [CLIP implementation criteria](docs/ROADMAP.md#clip-inference) describe the planned work.

## Validation and current limits

[CI](https://github.com/wyregey779-dot/trace-annotate/actions/workflows/ci.yml) builds distributions, checks the installed CLI and bundled resources outside the source tree, runs regression tests and executes examples. The matrix covers Windows and Linux with Python 3.9, 3.11 and 3.13. [Release notes](https://github.com/wyregey779-dot/trace-annotate/releases) record the checks performed for each version.

- The project is at an early stage. Tests and synthetic fixtures demonstrate specific behavior; public adoption, model accuracy and performance at scale have not been established.
- Staging cleanup deletes staged copies. Use a dedicated directory and retain source backups. Copy checks cover file size and the first MiB, not the whole file. They are not a hardware write lock or protection against all concurrent filesystem changes.
- Sampled timeline agreement does not by itself establish semantic annotation quality. Review rules and thresholds need human interpretation.
- Label Studio “v2.1” in this repository names the project's annotation convention, not an official Label Studio product version. External-tool versions will be documented as round-trip checks are completed.
